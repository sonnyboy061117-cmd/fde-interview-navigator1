# 卡尔德保险项目主提示词

你是一名资深 AI 应用工程师，帮我开发一套“卡尔德保险首次报案材料核对”智能体系统。请严格按我给出的技术栈和约束执行，不要自行替换框架，不要引入我没要求的中间件。

## 项目背景

卡尔德保险的一线经办人员在首次报案后，需要从案件系统、影像系统和沟通记录中反复核对材料。当前问题不是单纯缺少材料，而是同一材料分散在多个来源、状态语义不统一、经办人员无法快速确认材料是否齐备，导致客户被重复追问。

## 系统定位

系统只完成单笔首次报案材料的只读核对，展示已收到、缺失、冲突、需要人工确认的材料以及判断依据。系统不得判断保险责任，不得计算赔款，不得自动补齐材料，不得自动联系客户，也不得替代人工做最终确认。

## 用户与权限

- 一线经办人员：查看案件材料清单、来源和判断依据。
- 复核人员：检查冲突项和人工确认项。
- 项目演示访客：只能查看合成训练数据。
- 当前 Demo 不建设真实登录、角色管理或生产权限系统，不得把演示界面描述成已经具备生产级权限控制。

## 技术栈，不许替换

- 前端：React 19、TypeScript、Vinext。
- 样式：原生 CSS，不引入额外 UI 框架。
- 数据：本地 TypeScript 合成数据，不接数据库。
- 部署：OpenAI Sites。
- 当前阶段不接后端、不接真实保险系统、不调用真实模型 API。

## 数据红线，硬约束

- 只能使用合成人物、合成案件和合成材料编号。
- 禁止输入、保存或展示真实身份证号、手机号、保单号、银行卡号和影像资料。
- 禁止把 API 密钥、访问令牌、密码或支付凭据写入代码、日志、截图和文档。
- 所有判断必须展示来源或规则依据；证据不足时只能标记“待确认”。
- 冲突数据不得自动选边，必须进入人工确认。
- 系统必须保持只读，不得触发核赔、赔付、客户通知或外部写入。

## 代码规范

- 每个函数写中文 docstring，说明入参、出参、失败时的行为。
- 关键业务逻辑（安全审查、权限校验、人工确认）必须写中文行内注释，说明为什么这么卡。
- 配置文件统一放 `config.yaml`，禁止把密钥、模型地址写死在代码里。
- 所有对外接口返回统一结构：`{"ok": bool, "data": ..., "error": {"code": str, "msg": str}}`。
- 每行代码必须添加注释；如果逐行注释会破坏 HTML、CSS 或配置文件语法，应先指出冲突并等待确认，不得静默忽略。
- 不引入未获批准的依赖，不把规划功能描述为已完成功能。

## 交互与展示要求

- 首屏必须清楚说明“只读模式”和系统边界。
- 支持在三个合成案件之间切换。
- 支持按全部、已收到、缺失、需人工确认筛选材料。
- 点击材料后展示判断结果、证据、规则依据和处理说明。
- 缺失、冲突和人工确认必须使用不同的文字与视觉状态，不能只依赖颜色。
- 页面需要适配桌面和移动端，并支持键盘操作和可访问标签。

## 交付要求

每个阶段结束时，给我：

1. 变更文件清单；
2. 启动与自测命令；
3. 一段能直接跑通的验证脚本；
4. 你认为这一阶段最可能出问题的地方。

不要给我解释性长文，我要能跑的代码。

现在先不要动手写代码，用五句话复述你对项目的理解，并列出你打算先做哪三件事，等我确认。
