FDE 九阶段全流程：每一步在做什么，哪些步必须进虚拟实验室

访谈到底跟谁谈：六类角色，各有各的用处

别把"六个人都聊一遍"当成调研完成
① Buyer 业务决策者总经理、CIO、运营负责人级别。回答：值不值得投、谁出钱、谁拍板、能不能继续。用在 01-3 立项、07-3 继续决定
② Operator 一线执行者经办人、分析师、销售、普通员工、巡检员。回答：最近一单实际怎么做、哪里等、哪里返工、哪里做错。用在 01-2 基线、02-1 主力、07-2 验收
③ 技术/系统角色信息化负责人、FDE 集成工程师、设备适配工程师。回答：数据在哪、接口能不能通、技术边界在哪。用在 02-1、04-2 边界、08-3 交接
④ 风险/合规角色合规负责人、安全与发布审核。回答：哪些不能说、不能自动发、不能写进生产系统。用在 01-3 授权、08-1 三方评审
⑤ 下游接收者客服、服务台、财务。回答：上游出错时你收到什么、怎么补救、谁被投诉。用在 02-1 补异常路径、09-2 事件演练
⑥ 书面 Brief 持有人通常是业务负责人或项目对接人。回答：正式范围、交付时间、排除项写在哪份文件、哪个版本有效。用在 02-1 核对书面范围

问什么：七段提问结构 + 七个场景的具体问题

照着念就能问，但顺序别乱

先记住这个顺序：每次访谈都按这七步走

从"讲一件事"开始，到"还缺什么"结束；不要一上来问方案
  1. 还原事件："请讲最近一次……从谁发起，到这件事结束，中间经过哪些人？"
  2. 定分工："这一单里你负责哪一步？做完交给谁？"
  3. 量时间："处理和等待各花多久？中间被打断过几次？"
  4. 找异常："哪一单出过错？错在哪、怎么发现的、后来怎么补的？"
  5. 要证据："哪份记录、截图或系统能证明刚才说的？我能看一下吗？"
  6. 探边界："这件事你能定吗？谁批？什么情况必须停下来？"
  7. 收口："还有谁我应该去问？你觉得我问漏了什么？"

① 核基线（01-2 · 问一线）

目标：把"大概""经常"逼成具体数字
  1. "上一单从接手到交出去一共多久？其中等客户补材料占多久？"
  2. "这单返工了几次？每次是因为缺什么？"
  3. "你说的'一会儿'大概几分钟？能照系统时间给我两个时间点吗？"
  4. "这个数字是您记的还是系统里的？那条记录我能看看吗？"

② 问决策链（01-3 · 问业务负责人 + 风险）

目标：问出钱、问出权、问出红线
  1. "如果只批三个月试点，谁签字？预算从哪个口子出？"
  2. "除了您，还有谁的意见必须过一遍？"
  3. "哪些数据现在不能碰？碰了要谁批？"
  4. "试点结果不好的话，谁有权叫停？"

③ 六角色访谈（02-1 · 按角色换问法）

目标：六个视角各问到只有他知道的事
  1. 一线："最近一单实际怎么做的？和制度写的不一样在哪？"
  2. 业务负责人："您想改善哪个结果？现在这个数是多少？"
  3. 技术："数据在哪几个系统？接口谁维护？能不能只读？"
  4. 风险："这个动作错了最坏会怎样？谁承担？"
  5. 下游："上游交给你的时候，最常缺什么？"
  6. 财务/审计："收益怎么算您才认？"

④ 矛盾点追问（02-3 · 只问对不上的地方）

目标：不替任何一方改口，把分歧留在记录里
  1. "他说已经通知了，你说没收到——中间是哪个环节传的？"
  2. "两个部门的数字口径不一样，哪个是考核用的？"
  3. "这份文件是哪个版本？现在还有效吗？"
  4. "按您说的，这一单应该两小时，但记录显示两天，差在哪？"

⑤ 用户验收（07-2 · 问真实使用者）

目标：看他自己能不能做完，别替他点
  1. "不用我教，您能自己走完这一单吗？卡在哪一步？"
  2. "这一步比原来快还是慢？慢多少？"
  3. "这个结果您敢直接交给客户吗？不敢的话缺什么？"
  4. "如果明天系统停了，您打算怎么办？"

⑥ 上线三方评审（08-1）

目标：三方各自表态，不搞集体默认
  1. 业务："这个结果达到你的验收标准了吗？差哪一条？"
  2. 技术："版本固定了吗？回滚真跑过没有？"
  3. 风险："还有哪条权限没闭环？能不能上线？"
  4. "不同意的那位，具体反对哪一条？"

⑦ 交接与事件（08-3 / 09-2）

目标：确认对方真能接住，而不是签个字
  1. "下周我不在了，出故障你第一步做什么？"
  2. "回滚包在哪？谁有权限发？"
  3. "资料变更找谁批？改完怎么通知用户？"
  4. "你什么时候发现不对的？当时看到什么？"
  5. "上次改规则之后，有没有旧单据算错？"

五种问错的问法：问了等于白问

这几句话很顺口，但拿不到任何可用证据

❌ 反问式

  1. "您觉得 AI 能帮您做什么？"让客户替你设计方案，得到的是想象，不是事实。
  2. "是不是因为系统太老了？"诱导性提问，对方会顺着你点头。

❌ 平均值式

  1. "你们平均一天处理多少单？"平均值把异常全抹平了，要问最近一单。
  2. "这种情况多吗？""挺多的"不是证据，要问"上一次是什么时候"。

❌ 假设式

  1. "如果有个功能能自动填表，您会用吗？"假设性问题，答案没有验证价值。
  2. "要是能省一半时间，是不是就愿意上？"把意愿当成需求，后面验收一定翻车。

❌ 越界式

  1. "其他部门是不是也这样？"替别人回答，不可核实，也不能写进证据。
  2. "你们领导应该支持吧？"决策权要问决策者本人，不能替人确认。

✅ 一条通用替换原则

  1. 只要对方说"经常""有时候""一般"，立刻追一句："最近一次是什么时候？那次具体发生了什么？"
  2. 只要对方给了一个数字，追一句："这个数从哪来的？我能看一下原始记录吗？"
  3. 一次只问一个问题。连着问三个，对方只会回答最后一个。

怎么走：进实验室 / 出实验室的标准动作

  1. 从项目页进入 FDE 全流程，切到阶段 01 业务挖掘或 02 现场调研，页面顶部就是阶段工作台。
  2. 点 进入 3D 业务现场：案例项目用 /case-lab?case=案例key，集团项目用 /group-training 里选定的模块进入独立现场。
  3. 现场里先看六位角色的公开问题（问题提出人排第一，其余从业务、流程、技术、风险、下游五个视角核实），再逐个发起访谈。
  4. 访谈完成后在实验室里点 「将已访谈事实加入项目证据台账」——导入只是"待核实"，不等于确认需求，也不会自动完成任务。
  5. 点 「生成项目报告并交接」，报告带归纳依据、四来源状态和待核实问题，导出的文件进入阶段 02/03 的成果工作台。
  6. 回到全流程，在阶段 01/02 逐项填写任务结论、证据位置、责任人，再提交关卡评审。
⚠️ 两个最容易错的地方：① 阶段 03 之后不要再去找实验室入口，那里没有；② 实验室只记录"已采集事实"，公开开场陈述不算采集到的事实，六个人都聊完也不等于拿到了 Buyer / Brief / Industry / Operator 四种视角的完整证据。

系统表单怎么填

任务记录包含状态、结论、证据位置和责任人。结论按各任务的填写提纲组织，写明发现、影响和待验证事项。证据位置写材料名称、版本及页码或记录编号。责任人写能确认结果或跟进缺口的人。标记「已完成」时，结论、证据位置、责任人均须填写。

阶段关卡包含状态、评审人、依据和明确结论。选择「通过」前，本阶段三项任务须全部完成，前序关卡也须通过。修改任务记录后，本阶段及后续已通过的关卡会变成「待复核」。

华衡智造演练示例可用同一个 REQ-01 串起订单变更练习。以一次版本不同步的事件为起点，记录只读影响分析的需求，关联 Demo 版本、冲突样本和测试结果，再用试点记录核对返工变化。以下提纲可用于组织填写内容，证据编号和测量值以本次实训记录为准。
